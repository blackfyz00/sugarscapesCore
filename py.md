Мысли по параметризации симуляции и обеспечению детерминизма (сидов):

1. Управление сидом (Детерминизм):
Для полного воспроизведения симуляции (как в Minecraft по сиду) необходимо фиксировать генератор случайных чисел в самом начале работы скрипта. 
- Использовать встроенный модуль `random.seed(seed)` для стандартного `random`.
- Если где-то используется `numpy` или другие библиотеки случайных чисел, их также следует инициализировать (`np.random.seed(seed)`).
- Важно делать это до любых вызовов генерации карты, размещения агентов и начала шагов симуляции.

2. Структура конфига (Конфигурационный файл / Словарь):
Удобно представлять конфигурацию в виде словаря или загружать ее из JSON/YAML файла. Конфиг должен содержать:
- `seed`: целое число или `None` для случайного запуска.
- `grid_size`: размер карты (например, 100).
- `num_agents`: начальное количество агентов.
- `steps`: количество шагов симуляции.
- Флаги модулей (включение/выключение фич):
  - `enable_trade`: boolean (торговля).
  - `enable_aging`: boolean (старение).
  - `enable_reproduction`: boolean (размножение).
  - `enable_regeneration`: boolean (регенерация ресурсов).
- Параметры агентов:
  - Диапазоны начальных сахара и специй (например, `sugar_range: [15, 25]`).
  - Параметры старения (например, максимальный возраст `max_age`, если он не фиксирован или конфигурируем).

3. Архитектурные изменения в `main.py`:
- Вынести параметры из хардкода внутрь функции `main(config: dict)`.
- Обернуть шаги цикла в условные проверки по флагам из конфига (например, вызывать `age_agent` только если `config["enable_aging"]` истинен).
- Передавать `seed` в функцию инициализации и вызывать `random.seed(config.get("seed"))` в самом начале.

## Текущее состояние реализации

### 1. Управление сидом (Детерминизм):
- **`main.py`**: Считывает `seed` из `config.json`. Если `seed` присутствует, вызывает `rand.seed(seed)` в самом начале функции `main()`. Это обеспечивает детерминизм для стандартного модуля `random`.
- **`classes.py`**: `create_agent` использует `rand.randint` для `max_age` и `vis`. Поскольку `random.seed` вызывается в `main.py` до создания агентов, эти значения также будут детерминированы.
- **`create_map.py`**: Использует `rand.randint` для добавления шума к ресурсам, а также для генерации случайной карты, если `map.txt` отсутствует. Это также будет детерминировано благодаря `random.seed` в `main.py`.
- **`reproduce.py`**: Использует `rand.choice` и `rand.randint` для выбора пустой клетки и определения `vis` ребенка. Детерминизм обеспечен.

### 2. Структура конфига (Конфигурационный файл / Словарь):
- **`main.py`**: Загружает конфигурацию из `config.json`.
- **Параметры, считываемые из `config.json`**:
    - `seed`: Поддерживается.
    - `grid_size`: Поддерживается.
    - `num_agents`: Поддерживается.
    - `steps`: Поддерживается.
    - `sugar_range`, `spicy_range`: Поддерживаются для инициализации агентов.
- **Флаги модулей**:
    - `enable_trade`: Поддерживается, используется в `pipeline.py` для включения/выключения стратегии `interaction`.
    - `enable_aging`: Поддерживается, используется в `pipeline.py` для включения/выключения стратегии `aging`.
    - `enable_reproduction`: Поддерживается, используется в `pipeline.py` для включения/выключения стратегии `interaction`.
    - `enable_regeneration`: Поддерживается, используется в `pipeline.py` для включения/выключения стратегии `regeneration`.
- **Параметры агентов**:
    - `max_age`: В настоящее время генерируется случайным образом (`rand.randint(60, 100)`) в `classes.py` при создании агента. Не конфигурируется напрямую через `config.json` как фиксированное значение или диапазон, но детерминирован благодаря сиду.

### 3. Архитектурные изменения в `main.py`:
- **Вынести параметры из хардкода внутрь функции `main(config: dict)`**:
    - Функция `main()` не принимает `config` как аргумент, но загружает его из файла `config.json` внутри себя. Все ключевые параметры симуляции (размер сетки, количество агентов, шаги, диапазоны ресурсов) считываются из этого объекта `config`, а не захардкожены.
- **Обернуть шаги цикла в условные проверки по флагам из конфига**:
    - Это реализовано через механизм пайплайна в `pipeline.py`. Функция `build_pipeline(config)` динамически строит список стратегий (шагов симуляции) на основе флагов, таких как `enable_trade`, `enable_aging`, `enable_reproduction`, `enable_regeneration`, присутствующих в `config`. Таким образом, `main.py` просто итерируется по уже сконфигурированному пайплайну.
- **Передавать `seed` в функцию инициализации и вызывать `random.seed(config.get("seed"))` в самом начале**:
    - `main.py` вызывает `rand.seed(seed)` в самом начале, после загрузки конфига, что соответствует рекомендации.
